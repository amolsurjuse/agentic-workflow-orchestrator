# Simulator Access And Pricing

## Request

Provide three supported simulator unplug paths and show the applicable connector pricing on the driver HMI:

1. A registered driver can use the four-digit session code generated by `session-service` and supplied by the mobile app.
2. An administrator can use the configurable master code. The default requested value is `1711`.
3. A card-present charging session can be unplugged without a code because it has no ElectraHub driver account or mobile session.
4. The HMI shows the tariff, energy/time/session charges, idle fee behavior, grace period, idle cap, and session cap before authorization.

## Security Decision Matrix

| Session type | Submitted credential | Expected result |
|---|---|---|
| Registered/app session | Matching per-session code | Allow unplug |
| Registered/app session | Configured master code | Allow unplug |
| Registered/app session | Blank, malformed, or incorrect code | Reject unplug |
| Card-present session | Blank code | Allow unplug |
| Any active session | Charger or connector does not match | Reject unplug |
| Terminal session | Any code | Reject unplug |

The master code is configured by `SIMULATOR_MASTER_SECURITY_CODE` in `session-service`. It is never returned by an API or written to logs. Production can rotate the value without rebuilding an image.

## Runtime Flow

### Registered Driver

1. `session-service` creates a per-session four-digit code.
2. The iOS/Android active-session response carries a simulator URL containing that code.
3. Simulator UI reads the code without displaying it and requests validation.
4. Simulator backend resolves the physical connector reference and proxies validation to `session-service`.
5. `session-service` validates active status, charger, connector, and either the session code or master code.
6. After validation, the simulator emits the physical unplug/stop flow.

### Card Present

1. Simulator contactless authorization creates an OCPP card-present session.
2. `session-service` stores `paymentMethod=CARD_PRESENT` and exposes `securityCodeRequired=false` only in the internal charger-scoped active-session projection.
3. Simulator synchronizes this non-sensitive flag into its connector transaction state.
4. The HMI validates the unplug request with a blank credential.
5. `session-service` permits the action only when the stored session is actually card-present; the browser cannot declare this bypass itself.

### Administrator

1. Administrator opens the same protected unplug dialog.
2. Entering the configured master code follows the normal backend validation path.
3. Charger, connector, and active-session checks still apply.

## Pricing Source Of Truth

The HMI does not calculate prices locally.

1. Simulator requests `GET /api/v1/chargers/{chargerId}/connectors/{connectorId}/pricing`.
2. Simulator resolves the canonical OCPI connector reference, location, and connector type.
3. It calls the `session-service` internal connector-pricing endpoint.
4. `session-service` reads energy, time, parking/idle, and flat prices from the same `ocpi-connectors` Elasticsearch document used by session billing.
5. It reads idle grace period, idle cap, session cap, and applicable plan metadata from `pricing-service`.
6. The combined snapshot is rendered on the HMI and cached in the browser for 60 seconds to avoid repeated pricing calls during frequent connector/session refreshes.

OCPI parking price takes precedence as the connector idle rate. Pricing-plan values supply fallback idle behavior and monetary caps, matching session creation behavior.

## API Changes

### Session Service

- `GET /api/v1/sessions/internal/connectors/{connectorRef}/pricing`
- Extended `GET /api/v1/sessions/internal/active-by-chargers` items:
  - `paymentMethod`
  - `authMethod`
  - `securityCodeRequired`
- Existing `POST /api/v1/sessions/{sessionId}/simulator/verify-code` now accepts:
  - matching per-session code;
  - configured master code;
  - blank code only for a stored card-present session.

### Simulator

- `GET /api/v1/chargers/{chargerId}/connectors/{connectorId}/pricing`
- Existing code-verification proxy permits a blank code to reach the authoritative backend; malformed nonblank values are rejected at the edge.

## Performance Notes

- Pricing uses one connector-document lookup and one applicable-plan request when the HMI changes connector.
- The UI keeps a 60-second per-connector snapshot, so the 10-second active-session reconciliation loop does not create a matching pricing request loop.
- The active-session projection adds scalar fields only and does not introduce additional database queries.
- Unknown/older transaction projections default to code-required behavior.

## Validation

- Session Java unit suite, including session code, master code, invalid code, and card-present bypass.
- Simulator Go suite, including blank-code proxy, connector resolution, pricing proxy, and synchronized card-present metadata.
- Angular production build and ChromeHeadless suite, including tariff and cap rendering.
- Production smoke tests must verify:
  - registered session code unplug;
  - master-code unplug;
  - card-present code-less unplug;
  - invalid code rejection;
  - HMI tariff values against the connector GraphQL/Elasticsearch tariff;
  - displayed caps against the applicable pricing plan.
